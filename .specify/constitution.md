# 易闭环 Agent 宪法

## 当前里程碑技术栈

- 运行时：Node.js 22+，ECMAScript Modules。
- 依赖：核心 CLI 仅使用 Node 标准库；API 能力是显式、可选的 OpenAI-compatible HTTP 调用，不把密钥写入代码或实验目录。
- 交互面：先 CLI，桌面端只在内核通过反例实验后作为外壳接入。
- 持久化：仅写用户显式指定的实验目录，采用可审计的 JSON/JSONL 文件。

## 不可谈判的不变量

1. 每次行动前必须留下可证伪预期；无预期，不行动。
2. 每次行动后必须复观并验证；无法验证的结果不得计入已学知识。
3. 每次认知更新必须记录证据和归因；外部变化不得污染行动信用。
4. 硬约束优先于收益、探索和模型输出；无安全行动时 fail-closed 停机。
5. 选择层和执行器层都必须校验权限与安全边界，不能单点信任。
6. 事实、假设、目标、约束和模型建议必须分层保存；模型输出不是事实。
7. 同一初态、种子、事件序列必须可确定性重放；重放不一致视为系统错误。
8. Kernel 只能接收数值观测、ValueSpec 和实验空间级稳定的不透明 action token；不同实验空间随机置换 token。Kernel 不得接收或分支判断 worldId、scenarioId、领域标签和文件名。
9. 系统不能给自己颁发“自主/智能”证明：内置 challenge 只提供演示证据，真实性判断必须来自独立 Tester 晚绑定的生成世界与外部判别器；结论只能是“本轮未被证伪”。
10. CLI v0.1 不允许自修改代码，不允许操作真实桌面；WorldPort 不得删除用户文件。宿主不在进程内动态导入任意外部代码；显式 external adapter 只能通过受控 JSONL 子进程协议接入，外部输入还必须被整步摘要和 manifest 绑定的 Ed25519 公钥验签；当前不承诺 OS 沙箱或真实副作用安全。Runtime 仅可在实验目录内创建、追加或原子替换 Design §6 声明的账本、快照、锁、恢复证据和 challenge 子实验文件，并清理自己创建且可识别的 staging 文件；不得触碰其它文件。
11. UI、日志渲染、检查命令必须只读，不能改变世界、随机序列或学习状态。
12. 异常不得吞掉；持久化部分失败不得伪装成一次成功闭环。
13. 模型输出只能作为不可信提议；只有 Kernel 的安全选择、WorldPort 的执行回执和 verify/learn 的证据才能改变连续性状态。模型请求失败不得被伪装成成功行动。

## 工程与验证红线

- 只改与当前里程碑相关的文件，不顺手扩展真实 OS 权限。
- 契约、安全和 E2E 测试由独立 Tester 根据 spec 在实现前编写；反作弊 Oracle 是例外，必须在候选源码摘要冻结后由隔离 Tester 临时生成并立即执行，不能提前暴露给实现 worker。候选一旦修改，旧 Oracle 只能作回归，新一轮必须换 seed/生成世界。
- 每个功能层必须运行真实命令；解析成功或模块导入成功不算功能通过。
- 每层连续两轮无 High/Medium、测试不回退且无越界才算收敛。
- 终局要求：全部自动测试、真实 CLI E2E、事件重放、故障注入和异构复审通过。

## 人工卡点

- 当前里程碑不涉及金额、生产变更或跨仓库契约。
- 接入真实桌面写操作前必须另过人工闸：列明权限范围、预览、撤销和最坏损失。
- 发布、安装为系统级命令或打包桌面端前必须另行确认。
